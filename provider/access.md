# 准入策略

决定谁能租你的东西。Share Market 和 Client Market **共用同一套机制**。

## 四个作用域

准入按四个作用域**独立**配置，各有各的默认模式：

| 作用域 | 默认模式 | 覆盖 |
| --- | --- | --- |
| `share/free` | 黑名单 | 免费拼车位 |
| `share/paid` | 白名单 | 付费拼车位 |
| `client_host/free` | 黑名单 | 免费主机 |
| `client_host/paid` | 白名单 | 付费主机 |

**黑名单**：默认放行，只挡你明确拉黑的人。未知用户可以先来体验。

**白名单**：默认拒绝，要你明确允许某人**并授予 USD 信用额度**才能租。

这套默认值的逻辑很直接：免费的东西降低门槛让人试，付费的东西你得先认识对方才敢赊账给他。

## 在哪儿配

| 页面 | 干什么 |
| --- | --- |
| `/account/market-access` | 准入策略、交易对手、准入申请、买家授信、公共额度 |
| `/account/market-readiness` | 运营就绪摘要：收款资料、待准入数量、账务待办、四项策略状态 |

`/account/market-readiness` 只是聚合视图，实际写操作还是分别在收款信息、市场准入和市场账务页面完成。

## 处理准入申请

白名单模式下，买家点「租用」会生成一条准入申请。你可以批准、拒绝或取消。

**批准的同时要授予信用额度。** 系统用的是 libSQL Immediate 事务，所以不会出现「已允许但没授信」这种半吊子状态；批量保存也不会只存一部分买家。

## 两种额度

| 类型 | 说明 |
| --- | --- |
| **私有额度** | 你单独授给某个买家的 |
| **公共额度** | 把某个付费作用域切成黑名单模式后开放的通用额度 |

额度可以是有限的，也可以是无限的：

- **有限额度**：用到 80% 时双方预警，用满自动出账并暂停服务
- **无限额度**：不会自动出账，只接受主动清账

新手建议从有限额度开始。

## 拉黑

黑名单模式下把某人加进黑名单，他就租不了这个作用域下的东西。

「回收并拒绝」是一步到位的版本：收回当前租约 + 禁止以后再租。

## 永久关闭赊账关系

这是最重的操作，**随时可用**，即时生效：

- 即使还有待处理账单，关闭意图也会**立即锁定并终止服务**
- 清账或账单作废后**不会恢复**
- 之后双方**禁止再次建立付费租约**

用于对方长期不结账或有其他严重问题的情况。不可逆，想清楚。

## 逾期限制

买家逾期不结账会被限制继续使用市场赊账。解除条件只有两个：

- 你确认到账
- 管理员作废该账单

## 外部系统接入

准入接口除了浏览器 Session，也支持带 scope 的用户 API Token：

- `market:access:read` —— 读
- `market:access:write` —— 写

所有更新走 revision 乐观并发控制，`PUT` 请求必须提交当前资源的 `expectedRevision`，新资源提交 `0`。提交旧 revision 会冲突失败，不会覆盖别人的新设置。
