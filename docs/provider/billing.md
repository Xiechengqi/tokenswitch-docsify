# 账务与收款

你是供应商这一侧。买家侧的同一套流程见 [计费与付款](/share-market/billing)。

## 先说边界

**平台不经手钱，也不抽成。** 没有托管、没有余额、没有提现。

系统只做三件事：算出你该收多少、告诉双方、记录付款声明和你的确认。**钱怎么到你手上，是你和买家之间的事。**

## 先把收款资料填好

收费之前必须做的第一件事：在 `/account/payments` 填收款方式和联系方式。

出账时系统会把**当时的**这份资料冻结进那张账单。之后你改资料，不影响已出的账单 —— 买家付的是账单上写的那份。这既保护你也保护买家，避免资料变更改变未结账单的付款依据或争议证据。

`/account/market-readiness` 会提示收款资料是否齐全。

## 一本账

每一对「买家 × 供应商」有且只有一本 USD 赊账账户，**Share 和主机合并**。

同一个买家从你这租了三个拼车位加一台主机，就是一本账，一起出。

汇率默认 `1 USD : 7 CNY`，由 Router 管理员维护。未出账估算按当前汇率折算，**账单出具时冻结当时的汇率、人民币总额和明细**。记账始终是 USD，CNY 不参与计算。

## 收入怎么算

```text
授权服务开始
 └─► 前 12 小时健康服务时长：不计费（买家试用）
      └─► 之后按 Router 观测到的健康服务区间累计
           ├─ 服务不可用的时间：不计费
           └─ 状态未知的时间：不计费
```

**「有疑问的时间不算钱」这条规则偏向买家。** 你的机器越稳，收入越接近理论值。反过来说，隔三差五掉线是直接的收入损失。

免费位完全不进这个系统。

## 什么时候出账

| 触发 | 说明 |
| --- | --- |
| 额度用满 | 有限额度累计到上限 |
| 买家主动清账 | |
| 你主动清账 | 随时可以发起 |
| 最后一个服务结束 | 你和这个买家之间不再有活跃服务 |

**有限额度用到 80% 时双方预警。**

**出账即暂停相关服务**，直到你确认到账。注意固定期限**不会因此顺延** —— 买家拖着不付，损失的是他自己的服务时间。

无限额度不会自动出账，只接受主动清账。

## 确认到账

```text
账单生成
 └─► 买家线下付款（按账单上冻结的收款资料）
      └─► 买家在系统里声明已付（可带 reference / 备注 / 凭证）
           └─► 【你核验实际到账】
                └─► 你确认 → 仍在有效期内的服务恢复
```

**中间那步是你的责任。** Router 只记录链下付款声明，它不知道钱有没有真的到。**你必须独立核验**再点确认。

只有你确认到账，或管理员作废账单，才会解除对该买家的逾期限制。

如果买家声明了但钱没到，拒绝这次声明。

## 在哪儿看

`/account/billing`，按待处理 / 应付 / 应收 / 历史 / 管理员争议分区。

你既可能是供应商（应收）也可能是买家（应付），在同一页。

用量看 `/account/provider-usage`。

## 争议

买家可以对账单发起争议，由 Router 管理员裁决，管理员可以作废账单。

争议信息（原因、金额、付款 reference、凭证 URL）在系统内是**公开可读的事件数据**。API key、token、密码、私钥这类东西绝不能出现在里面 —— 后端会拦，但别去试。

## 永久关闭赊账关系

你可以随时永久关闭对某个买家的赊账关系：

- 即使有待处理账单，关闭意图也**立即锁定并终止服务**
- 清账或作废后**不恢复**
- 之后双方**禁止再次建立付费租约**

## 特殊情况

你租自己的付费主机按免费处理，不会形成自债务。
